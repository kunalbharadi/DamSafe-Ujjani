## Stable API contract for Prompt 3B

All endpoints are project-scoped under `/api/projects/{project_id}`. The run detail/status endpoint returns persisted `QUEUED`, `RUNNING`, `SUCCEEDED`, `FAILED` or `CANCELLED`, including progress/heartbeat, error and postprocessing evidence where present. There is no synthetic numerical fallback. A run's data is resolved only through its own successful row or an explicitly cached identical-config source row in the **same project**, followed by normalized-file SHA-256 verification. A missing or changed output returns 409; a run outside the project returns 404. A successful native solve is not scientific validation.

| Endpoint | Contract |
| --- | --- |
| `GET /api/projects/{id}`; `GET /api/projects/{id}/datasets`; `GET /api/projects/{id}/readiness?scenario_id=...` | Project, source inventory and immutable snapshot readiness. |
| `POST/GET /api/projects/{id}/scenarios`; `GET /api/projects/{id}/scenarios/{scenario_id}` | Immutable scenario snapshot, hash and input mode. Site run requests require this ID. |
| `POST/GET /api/projects/{id}/runs`; `GET /api/projects/{id}/runs/{run_id}`; `POST .../cancel` | Submit, poll progress/status, inspect failure and cancel. Idempotency keys are scoped to the project; reuse with a different request returns 409. |
| `GET .../runs/{run_id}/results/metadata` | Engine, pinned source commit/image, input/configuration hashes, source run, cached flag, units, CRS, vertical reference, nodata encoding, source-clock origin, absolute start when timezone-qualified, source-local clock when supplied, elapsed seconds, frame/cell counts and threshold/precision. Unknown time/datum values remain null or explicitly local. |
| `GET .../results/window?bbox=xmin,ymin,xmax,ymax&field=h&first_frame=0&frame_count=1` | Native numerical `h`, `eta`, `u`, `v`, `wet` or computed velocity magnitude in result-CRS **metres**, with cell centres/areas, elapsed times and per-value `WET`, `DRY`, `NODATA`. A bbox must select at most 2,048 cells; a request covers at most 32 saved frames. No cells yields `NO_CELLS_IN_WINDOW`. |
| `GET .../results/series?cell=0&first_frame=0&frame_count=...` | Per-cell depth time series and wet/dry/nodata state; absent count returns up to 32 available frames. Invalid cell yields `OUTSIDE_DOMAIN`. |
| `GET .../products/window?bbox=...&field=maximum_depth_m` | Per-cell `maximum_depth_m`, `maximum_velocity_m_s`, `flood_duration_s`, `arrival_elapsed_s`, or `cell_state`, in a 2,048-cell metric window. Each cell has `REACHED`, `NOT_REACHED` or `NODATA`; an empty bbox returns `NO_CELLS_IN_WINDOW`. |
| `GET .../products/area?first_frame=0&frame_count=...` | Up to 32 saved-frame flooded areas in m² at the documented threshold, with **separate unknown area**; unknown cells are never counted as dry. |
| `GET .../products/location?name=...&x=...&y=...&radius_m=...` | Nearest reporting cell within radius, its arrival state/time, sample offset and up to 32 depth frames. No cell within radius yields `OUTSIDE_DOMAIN`. |

`configuration_hash` includes the immutable request (excluding the transport idempotency key), pinned engine image/source commit and exact official input-file hashes. A changed request creates a new run ID and configuration hash; an identical successful verified result creates a **new** run ID explicitly marked `cached`, with `cached_from_run_id`/`source_run_id`. A failed, incomplete, changed or checksum-mismatched output cannot satisfy the cache. Site snapshots cannot yet execute because the hydraulic inputs are unverified; snapshot hashes and IDs remain distinct.

## Product semantics and limits

The worker reads one native saved frame and at most 2,048 cells at a time, copies geometry in blocks, caps product jobs at 2 million cells and 10,000 frames, and atomically writes `products.nc`. Responses return small metric windows instead of complete arrays. Input units must be seconds, metres and m². `maximum_depth_m` is the maximum over available valid saved frames, while `maximum_velocity_m_s` uses valid wet frames with both horizontal components; `valid_frame_count` records depth coverage. Velocity is unavailable if either component is missing. Flooded area is the sum of **known** cells whose saved depth meets `arrival_threshold_m`; `unknown_area_m2` is reported separately. For the synthetic closed tank no permanent-water baseline is defined. External baseline masks and site flood-area claims are blocked until a surveyed/georeferenced baseline is verified.

Arrival is the **first saved output frame** at or above the threshold, with no interpolation. The crossing is bracketed by that frame and its immediate predecessor only if the predecessor is valid and below threshold. If the first frame is already above threshold, onset before recording is unbracketed. A full-validity cell with no crossing is `NOT_REACHED`; an incomplete cell without a crossing is `NODATA`; a documented crossing remains `REACHED` even if another frame is missing. `flood_duration_s` is a left-held saved-frame estimate (final frame adds no interval) and becomes nodata when *any* required frame for that cell is missing. `DRY` is a valid instantaneous numerical depth below the wet threshold, distinct from all three arrival states. Flood extent is derived from spatially explicit solver state on the model mesh/columns, never from terrain selection below an arbitrary level. For SPH, area/columns are per unit breadth and cannot be presented as Ujjani floodplain area.

## Verification and outstanding scientific work

On this checkout, `DAMSAFE_REQUIRE_NATIVE_EVIDENCE=1` made absence of the retained D-Flow output a failure, and the complete Python suite passed **33 tests, 0 failures, 0 skips**. The native integration test verified that product flooded area equals a direct sum of saved D-Flow depths and cell areas, that other projects/runs cannot retrieve this output, and that frame limits are enforced. Focused tests also cover nodata, dry and arrival states, short series, cell-window bounds, changed configuration identity, valid-only cache reuse and corrupt-cache rejection. `ruff check backend scripts` passed. These software checks do not assess site accuracy. The native result was computed in Phase 2; Phase 3A read and derived from it, but did not execute a new solver run.

Prompt 3B can consume the listed endpoints and status/state labels and render a scientific result viewer for **labelled synthetic solver runs**. It must handle 404/409/422, null metadata/field values, explicit cache provenance, metric bounded windows and no site result. It must not display synthetic/example output over Ujjani, imply a complete breach or historical simulation, or treat model agreement as truth accuracy. Site maps, permanent-water exclusion, geospatial exports and exposure remain gated by verified Ujjani terrain/channel geometry, structures, roughness, boundaries, complete Q(t), clock/datum and executed site runs. Computed breach also requires verified component/method and level–storage/release-pathway evidence.
